Job Analysis and Job Evaluation Framework split by Technical, Operational, and Sales categories

How to use this framework: Each role must first be classified into a category (Technical, Operational, or Sales) before Job Evaluation scoring. The category determines which measurement lens to apply and which grade band is most likely.
Technical
Specialist / Expert roles
Roles where the primary value is domain expertise, solution design, or system architecture. Measured by solution quality and knowledge depth.
Operational
Process / Delivery roles
Roles that ensure consistent execution, compliance, and process excellence. Measured by throughput, accuracy, and SLA adherence.
Sales
Revenue / Client roles
Roles that directly influence pipeline, conversion, or revenue. Measured by win rate, deal size, and pipeline contribution.

Classification decision tree

Ask thisIf yes → categoryIf no → try next
Does the role own or design a technical solution?TechnicalContinue
Does the role directly own revenue, win rate, or a client relationship?SalesContinue
Is the primary output process adherence, delivery, or coordination?OperationalRe-examine scope

Hybrid roles (e.g. Solutions Presales)

Some roles span two categories. For a hybrid, assign the primary category based on where 60%+ of the role's accountability sits, then note the secondary category as context. This affects the grade anchor point.
70% Technical + 30% Sales → anchor on Technical track Grade: C4–D1 likely
Technical track
Typical roles
Solutions Architect, Data Engineer, Presales Specialist, Cloud Consultant, AI/ML Engineer, Principal Engineer
Primary output
Technical solution design, feasibility assessments, architecture proposals, RFP/RFI responses, technical enablement

Measurement criteria

Solution quality Proposal accuracy & feasibility rate
Time to solution Avg days from brief to proposal
Partner alignment % proposals aligned to partner specs (e.g. Microsoft)
Enablement reach No. of sales staff technically enabled per quarter
Rework rate % proposals requiring major revision

Key questions for Hiring Manager

  • Is this role the final technical authority, or does a senior architect review the design?
  • Does the role need to translate client business needs into architecture independently?
  • Are the technical domains genuinely integrated (e.g. data pipelines + cloud + analytics), or siloed?
  • What happens to the solution if this person is unavailable — is there a backup or does delivery stop?
Operational track
Typical roles
Project Manager, Delivery Lead, Operations Analyst, Bid Manager, Process Owner, Service Delivery Manager
Primary output
On-time delivery, process compliance, SLA adherence, bid coordination, resource scheduling, reporting accuracy

Measurement criteria

On-time delivery % milestones or submissions on schedule
SLA adherence % incidents or requests resolved within SLA
Process compliance Audit pass rate or error rate
Bid throughput No. of RFP/RFI submissions per quarter
Coordination span No. of stakeholders or teams managed

Key questions for Hiring Manager

  • Does this role own a revenue number, or is revenue a by-product of another metric (e.g. technical win rate)?

The grading question for hybrid roles

Accountability vs. guidance — before finalising a grade, ask: is this role accountable for team outcomes (→ D-level / Manager), or does it guide others while remaining individually accountable (→ C-level / Senior Specialist)? Getting this wrong shifts the grade band by one full level.
